ITC2 Parking Management — เวอร์ชัน 12 (ซิงก์สดผ่าน Firebase Firestore)
===================================================================

สิ่งที่เปลี่ยน
  - ข้อมูลเก็บที่ Firestore คอลเลกชัน "parkings" (1 เอกสาร = 1 รายการ ฟิลด์ docKind = zone / perm / temp / trash)
  - ใช้ db.collection('parkings').onSnapshot(...) ดึงข้อมูลสด: เพิ่ม/แก้ไข/ลบจากเครื่องไหน ทุกเครื่องที่เปิดอยู่อัปเดตทันที
  - กฎธุรกิจเดิมครบ: ประเภทผู้จอด "ลูกค้า", หมดเวลา = ขีดฆ่า + ตัดออกจากความจุทันที, หน้าตึก 2.2 / โรงไฟฟ้า จอดอิสระไม่มีช่อง,
    ตารางประวัติเรียง "ใช้งานอยู่" ไว้บน "หมดอายุ" ไว้ล่าง, ถังขยะ 30 วัน, ประวัติเวลาแก้ไข
  - ถ้าเชื่อม Firebase ไม่ได้ (ออฟไลน์/ถูกบล็อก/สิทธิ์ไม่ผ่าน) แอปใช้ข้อมูลในเครื่องแทน และแสดงสถานะที่ป้ายมุมขวาบน
  - ครั้งแรกที่ฐานข้อมูลกลางว่าง: ถ้าเครื่องนั้นมีข้อมูลเดิมในเครื่อง ระบบถามว่าจะอัปโหลดขึ้นระบบกลางหรือไม่

ต้องตั้งค่าใน Firebase Console ก่อนใช้งาน
  1) Build > Firestore Database > Create database
  2) แท็บ Rules ต้องอนุญาตคอลเลกชัน parkings เช่น (สำหรับทดสอบ)
       rules_version = '2';
       service cloud.firestore { match /databases/{database}/documents {
         match /parkings/{doc} { allow read, write: if true; } } }
     คำเตือน: กฎนี้ทำให้ "ทุกคนที่มีลิงก์" อ่าน/แก้/ลบข้อมูลได้ (คีย์ใน firebaseConfig ไม่ใช่ความลับ
     ความปลอดภัยขึ้นกับ Rules) ก่อนใช้งานจริงควรเพิ่มการล็อกอิน (Firebase Authentication) แล้วเปลี่ยนเป็น
     allow read, write: if request.auth != null;  (หรือจำกัดอีเมลบริษัท)
  3) นำขึ้น Netlify/Vercel (ลากโฟลเดอร์ไปวาง) — หน้าตัวอย่างใน Claude บล็อกการเชื่อมต่อภายนอก จึงซิงก์ไม่ได้ที่นั่น

ข้อควรรู้
  - ปุ่ม "กู้คืนจากไฟล์สำรอง" และ "ล้างข้อมูลทั้งหมด" มีผลกับระบบกลาง ทุกคนเห็นทันที (มีข้อความเตือนในหน้าต่างยืนยัน)
  - ถ้า 2 คนแก้รายการเดียวกันพร้อมกัน ฉบับที่บันทึกทีหลังชนะ (ระดับรายการ)
  - ระบบยังไม่ระบุว่าใครเป็นผู้แก้ (บันทึกเฉพาะเวลา)
